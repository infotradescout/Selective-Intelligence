When AI builds the wrong thing

Why AI-generated code can pass tests and still miss what you wanted, and how Selective Intelligence reopens intent before changing more code.

Why can AI-generated code look correct and still be the wrong product?

Because the AI may have optimized a fluent interpretation, a familiar product pattern, or the code that already exists instead of the person’s real job. Selective Intelligence treats that mismatch as a Step 1 failure: recover the intended outcome again, trace it into behavior, then correct the system rather than defending the implementation.

Signals that this is the problem

  • The code runs, but the person says, “That is not what I meant.”
  • Tests prove internal consistency while the real user journey is still wrong.
  • A correction gets treated as a new feature instead of a repair to the active understanding.
  • A dashboard, landing page, workflow, or architecture was chosen because it was familiar.

What Selective Intelligence does

  1. Preserve the person’s exact outcome, prohibitions, and corrections as the authority.
  2. Generate at least one plausible wrong reading and compare its real consequences.
  3. Treat existing code and documentation as evidence, not automatic proof of intent.
  4. Trace intent to requirement, implementation surface, observed behavior, and current proof.
  5. Fix the causal mismatch and re-run the end-to-end user path at the exact revision changed.

What proves improvement

  • The observable result matches the person’s stated job, not only the technical symptom.
  • The counterfactual “could every test pass while the person still says this is wrong?” is false.
  • Remaining uncertainty, client limits, and untested states stay visible instead of becoming “done.”

Boundary: Selective Intelligence cannot make an ambiguous irreversible product decision on the person’s behalf. It resolves what evidence can settle, makes reversible progress where safe, and asks one plain question only when competing outcomes would materially differ.
